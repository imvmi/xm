# 数据库结构

SQLite 与 MySQL 使用相同的逻辑表结构。当前为开发版本，不提供任意旧表结构、旧 JSON 配置或旧媒体目录的升级迁移。本次采集设置与任务队列变更支持原有数据库原地升级：新增滚动随机浮动、时间线边界、限流预设、浏览器生命周期、媒体重试、正式任务队列、任务模式、历史基线状态及运行记录关联字段，将不足 1 小时的自动采集周期提升至 1 小时，其他设置和历史记录保留。`migrate-mysql` 只用于同版本 SQLite 到 MySQL 的数据导入。

## 启动与配置

SQLite 默认文件名为 `xm.db`；启动 YAML 的 `database.sqlite_file` 可指定数据目录内的 `.db` 或 `.sqlite` 文件。为兼容旧部署，未指定文件名且不存在 `xm.db` 时，会继续使用已有 `archive.sqlite`，不会悄悄新建空库；明确配置的旧文件名不变。

设置页支持 MySQL → SQLite：默认迁移到 `xm.db`；若目标或其 WAL/SHM 已存在，则使用独立的 `xm-migrated-<id>.db`，绝不覆盖已有数据库。完整迁移包括业务配置、管理员凭据、队列和归档；迁移记录独立存放于数据目录的 `migration-state.json`，不随源数据库切换丢失。复制期间禁止应用写入，校验完成后受控重启。源 MySQL 保留但不再同步新增数据。

设置页也支持 SQLite3 → MySQL：只读预检确认目标为空，正式执行时获取目标工作锁后建表。所有数据在单个事务中复制并逐表核对行数与内容 SHA256，保留二进制密码盐/哈希、NULL、Unicode 和长字符串 ID。校验完成后备份并切换启动配置、重启应用；迁移记录保存目标标识用于重启确认，不保存或返回连接密码。非空目标拒绝覆盖；提交后切换失败时保留源库与目标副本，重试需检查目标状态或另选空库。

S3 / WebDAV → 本地采用逐文件提交：下载到本地临时文件，验证大小、SHA256、同步磁盘并回读后，条件更新 `media.storage_id/local_path/object_key`；失败保持原引用，不修改下载重试计数。原远端对象保留；默认媒体目的地改为 `local`，其余源连接保留供未迁移文件读取。

本地 → S3 / WebDAV 会先验证目标连接，成功后持久化目标连接与默认存储。历史文件通过受限数据目录访问，验证本地大小与 SHA256 后上传到带内容哈希的对象键，远端回读验证后条件更新媒体索引。源本地文件保留；数据库更新失败后再次执行会复用已验证的目标对象。两种方向都仅处理源位置中状态为 `done` 的媒体，新下载使用新的默认位置。数据库迁移与存储迁移共用单任务互斥与暂停恢复机制，界面分别提供配置入口。

仓库没有预置配置文件。直接运行 `xm serve`，按数据库 → 媒体存储 → 管理员账号完成首次设置。连接测试阶段不生成配置；最终提交阶段生成私有的 `config.yaml`，随后在一个数据库事务中写入管理员和运行设置。若提交结果不确定，保留配置文件中的目标数据库地址，重启时据该数据库的真实状态判断是否初始化完成。

YAML 仅保存 `data_dir` 与 `database`。其他持久化设置均在数据库中：

| 表 | 主键 | 职责 |
|---|---|---|
| `account_preferences` | `target` | 独立保存账号首页显示偏好，取消监控后保留；随 SQLite/MySQL 数据库迁移复制 |
| `schema_meta` | `id=1` | 当前数据库结构版本和更新时间 |
| `admin_accounts` | `id=1` | 管理员用户名、32 字节密码盐与哈希、初始化锁定标记 |
| `system_settings` | `id=1` | 代理、浏览器参数与生命周期（同时控制任务时限）、滚动基础等待与随机浮动、空闲等待、已归档边界、429 限流策略、队列任务间隔、媒体大小与重试、自动采集周期、全局暂停、当前存储 ID；旧版独立任务时限（`collection_timeout_seconds`）及条数/页数/滚动上限列为兼容保留，不参与新任务调度 |
| `storage_profiles` | `id` | 本地/WebDAV/S3 连接及各自凭据，内置 `local` 记录 |
| `notification_channels` | `id` | Telegram/Webhook 渠道、接收位置、凭据和启用事件 |
| `x_cookies` | `id=1` | 明文 `auth_token`、`ct0` 及更新时间 |

配置采用独立字段，不将整份配置塞入一个 JSON 字段。当前存储通过外键指向 `storage_profiles`；更新设置时禁止移除已有媒体引用的连接。管理员与运行配置原子提交，重复初始化不能覆盖管理员。管理员存在而系统配置缺失时启动报错，不会回到开放注册状态。

管理员密码只存加盐哈希；X Cookie、代理凭据、存储密钥和通知 Token 不做应用层加密。管理 API 不回显这些秘密值。会话保存在内存，服务重启后重新登录。

## 归档与媒体

界面显示设置还包括视频默认静音（默认开启）、循环播放（默认关闭）、原图客户端缓存时长（默认 168 小时，可设 1～720 小时）、原视频客户端缓存时长（默认 10 分钟，可设 1～1440 分钟）。均以独立字段保存在 `system_settings`，SQLite/MySQL 启动时自动补列；数据库迁移保留这些设置。视频播放前只显示统一比例的占位框，不设置媒体 `src`、不预读视频、不生成封面；点击后按静音与循环偏好播放原文件，单击画面在全屏与时间线内嵌框间切换，保留同一视频实例和播放进度；独立控件支持播放/暂停、声音和进度调整。不支持或拒绝浏览器全屏时使用铺满页面的备用模式。切换页面或重新加载时间线时停止并释放视频。

已归档媒体以 SHA-256 标记 URL 版本并返回 ETag，启用 `private` 浏览器缓存和 `Vary: Cookie` 会话隔离；头像缓存固定为 1 小时。API、未登录响应、媒体错误响应仍为 `no-store`，旧的无版本媒体链接每次复用需校验，缺少有效哈希的旧媒体不启用长缓存。缓存过期后支持条件请求和视频 Range/If-Range；匹配远端媒体 ETag 时可直接返回 304，不访问 S3/WebDAV。远端本地缓存的访问时间不作为 Last-Modified。缓存有效期并非自动删除期限，也不能保证浏览器保存完整视频；修改设置只影响新响应，不会撤回浏览器已保存的原有效期。图片不压缩，视频不转码。

归档页使用轻量账号目录与独立统计接口：先显示身份、头像和监控状态，再补齐推文数、媒体数和最近归档时间。账号媒体统计按关联推文查询 `media(post_id,status)` 覆盖索引，包含递归引用并去重。账号统计与概览计数在服务端缓存 30 秒、合并并发刷新；采集结束或监控/设置变更后失效，页面“刷新”可强制重算。服务状态仍按原频率读取，统计缓存不影响采集或归档数据本身。

| 表 | 主键 | 职责 |
|---|---|---|
| `profiles` | X 用户 `id` | 最近确认的用户名、锁推状态、检查时间 |
| `target_identities` | `target` | 稳定归档键到 X 用户 ID 和当前用户名的绑定 |
| `posts` | 推文 `id` | 作者、正文、发布时间、回复/引用/转推 ID、原始 JSON、归档时间 |
| `post_bookmarks` | `post_id` | 独立收藏状态与微秒级收藏时间；外键关联推文，重复收藏保留原时间，取消再收藏重新排序 |
| `target_posts` | `(target, post_id)` | 目标时间线与推文的多对多关系 |
| `media` | `(post_id, media_id)` | 媒体来源、下载状态、本地路径/远程对象键、存储 ID、SHA-256、大小、重试次数及下次重试时间 |
| `media_directories` | `owner_key` | 作者身份到唯一媒体目录的固定映射 |
| `runs` | 自增 `id` | 每轮真实执行的目标、关联 `job_id`、起止时间、状态、数量及错误摘要 |
| `run_metrics` | `run_id` | 每页提交的读取与新增关联计数；旧记录缺失时不推算 |
| `request_budgets` | `scope` | 旧版本请求节流状态；新版本不再读取或写入，仅在清空限流状态时兼容清理，不存 Cookie 或请求 URL |
| `collection_progress` | `target` | 绑定用户 ID、两条时间线的分页游标、完成/明确耗尽状态和补采前顶部边界 |

`target_posts.post_id` 和 `media.post_id` 外键引用 `posts.id`。引用推文与主推文使用同一张 `posts` 表，同一事务递归保存；引用本身不额外加入目标时间线。`reply_to`、`quote_id`、`repost_id` 允许指向未返回或无权限读取的内容，因此不设强制外键。

`target` 是初始归档键，账号改名后保持不变；当前显示名从身份绑定中读取。移除监控只移除调度任务，保留归档、身份与通知去重历史，因此这些历史表不级联绑定到 `monitors`。

时间线索引在启动时自动补齐，适用于已有 SQLite / MySQL 8.4 数据库：`posts_timeline(length(id), id)` 与 `target_posts_timeline(target, length(post_id), post_id)` 支持全局及单账号倒序读取；字符串 Snowflake ID 按长度再按 ID 排序，保持不同时期 ID 的时间顺序。`posts_first_seen(first_seen)` 支持今日归档统计，`media_status_bytes(status, bytes)` 覆盖媒体数量与空间统计。已有主键、`target_posts_post(post_id)`、媒体状态及账号索引继续保留。首次升级建索引需要数据库 INDEX 权限及一定磁盘空间，时间取决于存量数据。

`/api/posts` 保留 `offset` 兼容入口，同时返回 `next_cursor` 和 `has_more`。页面后续请求使用 `before=<最后一条ID>&count=0`，避免深层 OFFSET 和重复计数；此时 `total=-1`，页面保留首批总数，刷新后重新统计。引用与媒体按页批量读取；普通时间线不展开全库引用，搜索和媒体筛选仅从当前归档范围展开。包含匹配的关键词搜索仍需检查正文，普通 B-tree 索引不能消除任意子串搜索的成本。

`section=bookmarks` 按 `(created_at, post_id)` 倒序查询收藏，使用独立的 `b:<微秒时间>:<推文ID>` 游标和 `post_bookmarks_recent` 索引；翻页不依赖游标对应的收藏记录仍然存在。省略 `target` 查询全部收藏，不应用监控账号的首页显示开关；指定 `target` 时限定为该账号已归档的推文及其引用，不按引用作者用户名猜测归属。搜索和媒体类型条件在收藏范围内生效。普通列表和引用均返回 `bookmarked` 与 `bookmarked_at`，前端同步同一 ID 的按钮状态。`PUT /api/posts/{id}/bookmark` 接收布尔值 `bookmarked`，要求管理员登录、同源与 CSRF 校验，迁移维护期间拒绝写入；收藏及取消接口均可安全重复调用。

已有数据库启动时自动创建收藏表，不改动原推文；SQLite3 / MySQL 双向迁移和命令行导入均包含收藏记录。旧 SQLite 命令行源文件缺少收藏表时按无收藏处理。

媒体目录为 `media/users/alice_123456/哈希.jpg`，其中 `123456` 为稳定 X 用户 ID，首次目录名写入后保持不变。引用媒体使用引用作者的目录。WebDAV/S3 对象键沿用相同层级，可添加连接前缀。数据库保存文件索引，文件内容仍保存在本地或远程存储。

## 调度与通知

| 表 | 主键/唯一键 | 职责 |
|---|---|---|
| `monitors` | `username`（稳定归档键） | 启用状态、下次执行、最近结果、普通推文/回复基线状态，以及跨批次补采使用的锚点 |
| `collection_jobs` | 自增 `id` | 手动、自动及重试任务的持久化 FIFO 队列；记录 `incremental` / `backfill` / `rescan` 模式、入队/开始/结束时间、状态、尝试次数、分页失败次数、下次重试时间和最近执行 ID |
| `web_state` | `key` | 少量持久化运行状态，例如登录受限、全局冷却 |
| `notification_targets` | `target` | 首次采集是否已完成，决定历史数据静默策略 |
| `notification_seen` | `(target, post_id)` | 新动态通知去重 |
| `notification_incidents` | `key` | 异常事件及最近提醒时间 |
| `notification_deliveries` | `id`；唯一 `(event_id, channel_id)` | 持久化发送队列、消息载荷、重试与结果 |

投递记录保留删除渠道后的历史，因此 `channel_id` 不设删除级联。载荷 JSON 是单次事件快照，不是渠道配置。

统一轮询周期和固定安全上限不再复制到每个监控账号。媒体临时失败按 `next_attempt` 退避，不支持或超限内容使用 `permanent` 状态；来源地址变化会恢复为待处理。采集记录全局保留最近 1000 条。

索引覆盖作者 ID、目标身份 ID/当前用户名、媒体状态/重试时间/存储 ID、目标采集记录、推文反向归属、到期监控和待发送通知。配置表对单例 ID、关键枚举、密码长度及周期/超时范围设置约束。

## 备份

备份数据库、自动生成的启动 YAML，以及本地媒体或远程对象。SQLite 应停服后复制数据目录，或使用一致性备份工具；MySQL 需要数据库快照或一致性导出。仅备份 YAML 不能恢复配置、Cookie 或归档内容。

分页断点、推文和本轮计数在同一事务中提交；记录不含请求 URL、Cookie 或认证头。`run_metrics` 随采集记录清理，`collection_progress` 在任务完成或显式重置后删除。

`collection_jobs` 是用户可见任务队列的事实来源，状态包括排队、运行、限流等待、登录等待和重试；已结束任务保留用于关联执行记录。时间线分页遇到连接失败、408/425/5xx 或响应体读取失败时，成功页面及下一页游标先持久化，任务按 5、15、45 秒（后续保持 45 秒）退避并移到队尾；服务重启保留下次重试时间。首次账号自动选择 `backfill`；基线完成或标为范围不确定后自动选择 `incremental`；`rescan` 会清除分页断点和基线判定，但不删除归档。`monitors.baseline_status` 使用 `not_started`、`backfilling`、`visible_history_complete`、`partial`、`blocked`，并分别保存普通推文和回复状态。只有 X 时间线响应明确结束才写入 `visible_history_complete`，稳定页面底部只写入 `partial`。`web_state.budget_batch_pending`（历史键名沿用）只保存自动批次尚未完成的账号集合，`budget_batch_failed` 保存当前批次是否曾发生采集错误。队列项在领取时与 `monitors.running` 一起提交，全局暂停、限流冷却和服务重启不会丢失剩余任务；运行中的任务在重启时恢复为排队状态。任务完成与队列推进之间崩溃时允许重试最后一个账号，数据与分页断点通过原有事务和去重逻辑保持一致；整个批次完成后，在同一事务中清空批次待办并统一安排下次自动采集。

账号目录统一展示监控与已有归档的并集。结构版本 16 新增 `account_preferences`，升级只创建空表，不修改既有归档或监控。已有监控仍读取其 `show_in_timeline` 兼容列；调整显示时同步保存偏好，取消监控时在同一事务中保存最新偏好、删除监控、取消队列并清理未完成断点。仅归档账号读取独立偏好，未设置时默认显示。重加监控继承该偏好，账号改名后沿用原归档标识。

## Samba 媒体与本地副本

`storage_profiles.kind` 新增 `smb`，共享地址保存为 `smb://服务器[:端口]/共享名`，沿用 `username`、`password`、`object_prefix` 和超时字段。旧 SQLite 表在事务中重建 CHECK 约束并验证外键；MySQL 扩展相应 CHECK，保留原连接与系统设置。SMB 密码与其他存储凭据相同，不向管理 API 回显。

`media_local_copies` 保存本地迁往远端后保留的源文件清单，包括媒体标识、本地相对路径、目标存储和对象键、大小、SHA256。清单与媒体引用在同一事务中提交，并随数据库迁移完整复制。清理只处理清单内、远端重新校验成功且不再被本地媒体引用的文件；删除后移除记录，遇到中断可重试。媒体清理不改变数据库、配置或远端文件。
